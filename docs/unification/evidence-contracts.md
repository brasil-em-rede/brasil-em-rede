# Contratos puros de fatos e evidências U05

Esta fatia define DTOs imutáveis, envelope JSON Schema Draft 2020-12 v1 e transições de revisão em memória. Não persiste, consulta catálogo, adquire fontes, resolve identidades, publica afirmações nem altera PostgreSQL/Neo4j.

## Identidade e proveniência

`FactEvent.event_id` é UUID de negócio fornecido explicitamente pelo produtor/aplicação; nunca é inferido de entidade, par, ano, valor, chave de registro ou versão. `event_identity` calcula a identidade de negócio no namespace estável `(source_id, dataset_id, event_id)`, excluindo `dataset_contract_version` e `source_record_key`. Assim, o mesmo UUID explícito conserva identidade entre versões e chaves de registro, enquanto UUIDs diferentes permanecem eventos distintos mesmo com os mesmos pares, anos e valores. Não existe UUID automático: falta de ID explícito gera `IdentityUnresolvedError` (subtipo de `ContractError`) e reconciliação sem regra aprovada permanece não suportada; não se inventa identidade.

`EntityRef` exige tipo textual não branco e permite referência não resolvida sem lookup. `ObservationRevision` exige `source_id`, `dataset_id`, versão do contrato, UUID do artefato, SHA-256 lowercase, localizador opaco e tipo de localizador, além da versão do schema do payload. `source_release`, parser, normalizer e horário observado ausentes permanecem nulos.

O `observation_id` é SHA-256 determinístico de uma tupla canônica versionada de origem/conjunto/versão, chave de registro quando fornecida, localizador, hash do artefato, versão do schema e conteúdo tipado, revisão/ação/predecessor. Não inclui relógio ou ID de execução. Artefatos/localizadores distintos ou payload alterado produzem observações distintas; replay idêntico é idempotente. Evolução de versão/chave pode manter identidade de evento, mas não autoriza reconciliar a cadeia: `apply_revision` conserva a recusa quando a revisão muda registro/origem ou não aponta ao predecessor exato.

## Fronteira pública JSON e canonicalização

`serialize_fact_envelope(event, observation, evidence=()) -> bytes` é a saída pública pura dos DTOs tipados para o envelope JSON UTF-8 determinístico. Usa o wire `br-acc-typed-json/v1` existente para valores de objeto/payload, preserva `EntityRef` e `EvidenceRef`, e não resolve identidades nem persiste. A serialização e `read_fact_envelope` exigem igualdade de `source_id`, `dataset_id` e `dataset_contract_version` entre evento e observação; o leitor repete essa validação antes de devolver o envelope, de modo que `apply_serialized_revision` não altera a cadeia em caso de divergência. Chave/localizador e regras de predecessor permanecem vinculados à cadeia do mesmo registro; igualdade da identidade de negócio entre versões/chaves não autoriza continuar outra cadeia.

`read_fact_envelope(raw: bytes | str) -> ValidatedFactEnvelope` é a entrada pública de JSON. Lê UTF-8 estrito; rejeita nomes JSON duplicados em qualquer profundidade e constantes não JSON (`NaN`, `Infinity`); verifica versão, campos obrigatórios/fechados e tipos da forma do envelope; decodifica os valores tagged `br-acc-typed-json/v1` pelo decoder existente; constrói `FactEvent`, `ObservationRevision` e `EvidenceRef`, que impõem invariantes semânticas; devolve DTOs imutáveis mais `canonical_bytes` determinísticos do envelope JSON normalizado. Erros do contrato saem como `ContractError`. `apply_serialized_revision(chain, raw)` chama esse leitor e só então entrega a `ObservationRevision` validada ao `apply_revision` real; uma falha no leitor não faz transição.

O JSON Schema publicado descreve forma estrutural/lexical: envelope e objetos fechados, tags/tipos, campos obrigatórios, enums e formatos disponíveis. A implementação Python **não carrega nem executa o arquivo JSON Schema** em runtime nem instala dependência para isso; faz as verificações estruturais finitas equivalentes diretamente e acrescenta decodificação/canonicalização e invariantes DTO. Draft 2020-12 não compara propriedades temporais dinâmicas, não verifica `repr(float)` shortest-round-trip e não consegue impor ordenação/unicidade de `pair[0]` em arrays de pares. O parser também é necessário para detectar nomes duplicados antes de sua perda no parse. Portanto, schema passa significa apenas forma estrutural, nunca prontidão para consumo; intervalos invertidos, float tagged não canônico, pares repetidos/desordenados e JSON textual ambíguo são rejeitados pela fronteira pública.

`canonical_json` preserva o wire tipado com cabeçalho `br-acc-typed-json/v1`: `["br-acc-typed-json/v1", [tag, value]]`. Tags suportadas: null, bool, int, float finito, string, Decimal finito, UUID, date, datetime consciente de fuso, array e object. Objetos tagged são pares de chaves ordenadas; o decoder exige chaves únicas/ordenadas e representações exatas de floats, Decimal, UUID, data e datetime. Objetos/listas de usuário continuam dentro das tags `object`/`array`, sem colisão com strings semelhantes a tags. O envelope retorna bytes JSON normalizados em separado; eles não substituem o `canonical_json` tipado usado nos valores/IDs.

`FactEvent.object` e payloads de revisão são copiados e congelados recursivamente na construção (mapeamentos tornam-se somente-leitura e listas tornam-se tuplas), de modo que alterações posteriores no valor original não mudam semântica nem IDs.

## Revisões e limites

Uma cadeia começa com `assert`; `correct` e `retract` acrescentam exatamente o próximo número e apontam para o ID da revisão imediatamente anterior, no mesmo registro namespaced. Retração não contém payload substituto e encerra a cadeia. Ausência é `None`/nenhuma chamada, nunca retração. Intervalos conhecidos são fechados e não podem inverter; tipos temporais precisam ser compatíveis e `datetime` exige fuso explícito. Erros são `ContractError` tipados.

A matriz desta fatia usa fixtures sintéticas offline e verifica o valor `RawArtifactRef`/`Manifest` sem chamar catálogo, rede, banco, armazenamento, serviços ou migrações. Testes formais Draft 2020-12 são separados das rejeições semânticas da fronteira pública. Issue #34 e gates operacionais U03, U07/U10 e F04 permanecem separados e não aceitos por este contrato.
